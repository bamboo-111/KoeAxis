# 说话人切换：小样本方案（2026-10-17，第二版：用现成方案，不自训模型）

## 目标

1. **必须**：字幕不跨说话人。换人处强制断开，split / normalize 必须遵守。
2. **可选**：给每条字幕标上说话人（固定主持人用名字，其他人记为“未知 / 嘉宾”）。

## 成熟方案：说话人分离 + 声纹注册匹配（不需要训练）

业界常规做法分两步，全部用现成模型：

1. **说话人分离（diarization）**：回答“谁在什么时候说”，输出匿名的 SPEAKER_00 / 01… 时间线。
2. **声纹注册匹配（identification）**：
   - 每位主持人提供一段 ≤30s 的单人干净语音作为“声纹”；
   - 把分离出的每个说话人与各声纹算相似度，超过阈值才命名，否则记为未知。
   - 阈值是唯一要调的参数。

“小样本”只体现在注册声纹上，模型本身不训练。

### 候选实现

| 方案 | 分离 | 声纹匹配 | 条件 / 成本 | 备注 |
|---|---|---|---|---|
| **A. pyannote 开源**（首选） | `pyannote/speaker-diarization-community-1` | 同一套 pyannote 嵌入模型，余弦相似度 + 阈值 | 本地 GPU；需你在 HF 页面同意协议并提供 token | 社区标准做法：注册片段整段取一个向量，阈值在自己的录音上调 |
| B. pyannoteAI 云 API | 商用 diarization | 官方 voiceprint 注册 + identification 接口，返回名字 / 未知和置信度 | 需注册付费 key；音频要上传 | 最省事；声纹 ≤30s、只含目标说话人、不限语言 |
| C. 现有 MOSS + 声纹 | MOSS-Transcribe-Diarize（已装、已测） | 另装一个嵌入模型（pyannote embedding / SpeechBrain ECAPA / 3D-Speaker CAM++）做匹配 | 本地，无授权问题（ECAPA / CAM++） | MOSS 切点已验证较准；每期约 +9 分钟 |
| 备选分离器 | DiariZen、NeMo Sortformer 等 | — | 本地 | 公开评测里表现不错，必要时再测 |

建议先做 A 和 C 两条本地方案对比（B 需要付费且要上传音频，作为保底），挑切点更准、误报更少的一条。

## 需要你做的

1. **声纹片段**（约 10 分钟工作量）：每位固定主持人 1–3 段，每段 10–30s，只有这一个人说话（无插话、笑声、BGM），最好来自不同期，用于覆盖录音条件差异。
   - 写成表：`期数, 开始秒, 结束秒, 名字`。
   - 我也可以先从 MOSS 结果里挑出“长段单人”候选，你只需确认是谁。
2. **少量测试标注**（用于选方案和定阈值，不用于训练）：
   - 2–3 期各 5–10 分钟，标出换人时间点。
   - 我先用分离结果生成 Audacity 标签文件，你只修正。
   - 已有素材可复用：广岛 #30/#34、25 期前 6 分钟的 25 条候选。
3. 如选 A：在 HF 上同意 `pyannote/speaker-diarization-community-1` 的使用协议，并提供 token；如选 B：提供 pyannoteAI key。

## 评测（标注到位后我来写打分脚本）

- **字幕级**：
  - 跨说话人字幕条数（改前 → 改后）；
  - 换人检测的精确率 / 召回率（容差 ±0.5s）；
  - 同一人被误切的比例。
- **时间线级**（只在输出标签时才看）：说话人命名准确率、未知率。
- 每期额外耗时与显存。

## 接入方式

- align 之后输出 `speaker_breaks.json`（时间 + 置信度），split / normalize 遵守高置信断点；低置信只出提示。
- 需要标签时，在 manifest 写 speaker 字段，导出时再决定 SRT 是否加前缀。

## 风险

- 固定几人对谈时，声线可能相近，需要在测试集上实测区分度。
- 「うん」「はい」等短附和很难判断说话人，可只要求“短附和不单独成条”。
- 多人同时说话、笑声段不计入评测。
