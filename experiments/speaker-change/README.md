# 说话人切换（换人处断句）旁路实验

不改动生产流程，只评估“字幕内部是否有换人”的检测方案。

## 文件
- `moss_chunks.py`：把音频切成固定长度的块，分块跑 MOSS-Transcribe-Diarize（说话人标签只在块内有效），输出 `chunks.json`。需在 MOSS 专用环境 `experiments/moss-transcribe-diarize/.venv` 中运行，并设置 `PYTHONPATH` 指向 `experiments/moss-transcribe-diarize/vendor/MOSS-Transcribe-Diarize`、`HF_HUB_OFFLINE=1`。
- `flag_cues.py`：对照成品 SRT，列出与两个以上 MOSS 说话人段重叠（各≥0.3s）的字幕。
- `speaker_listen.py`：广岛那期用来做 MiMo 听音判断切点的脚本（从会话临时目录移入）。
- `runs/`：实验输出。

## 2026-10-17 pyannote Community-1（第一阶段步骤 1/4）

脚本：
- `pyannote_diarize.py`（whisperx 环境 `.venv-whisperx312`，pyannote.audio 4.0.7）：整期分离，不指定人数；ffmpeg 解码为 16kHz 单声道后以波形传入（避开该环境缺少 soundfile / torchcodec DLL 的问题）。输出 `diarization.json`（regular / exclusive / 每簇声纹向量）。需要环境变量 `HF_TOKEN`；权重已缓存在用户目录 HF 缓存。
- `eval_breaks.py`（`.venv312`）：给对齐 token 打说话人标签 → 同说话人连续段 → 两侧各 ≥0.5s 为强断点；对照成品 SRT 列出跨说话人字幕，可同时对照 MOSS 和人工切点。
- `make_label_sheet.py`：三种检测（pyannote exclusive / regular、MOSS）候选的并集，生成待标注表和 Audacity 标签。

结果：
- **速度**：25 期 1932s 音频 30.1s，26 期 1763s 音频 27.5s（实时率约 0.016），显存峰值 1.6GB。比 MOSS（一期约 9 分钟、7GB）快约 18 倍。
- **说话人数**：25、26 期都自动估出 3 人；广岛（电视，含广告）11 人。
- **广岛**：两处人工确认的换人（93.46s、105.46s）都检出为强断点，误差 <0.1s。
- **25 期前 6 分钟**（110 条，已知真换人 10/12/50/51/64/86/90/94，注意这份清单本身是从 MOSS 候选里挑的，偏向 MOSS）：
  - exclusive + token 映射：含强断点 17 条，命中已知 12/50/94（64 为弱断点），漏 10/51/86/90；
  - regular（字幕内 ≥2 人各 ≥0.3s）：标出 29 条，命中 6/8，漏 10（齐声问好）、86（0.7s 短句）；
  - MOSS：标出 25 条。
- **问题**：
  - 快速接话、不足 1s 的短句（「そう」「3人でね」），pyannote 常检不出，或只在 regular 里作为重叠出现、exclusive 里被丢掉；
  - 几位主持人音色相近，有一处前后两人被并进同一簇（第 51 条）；
  - 有些强断点落在词中或句中（「WBC｜について」「って｜思います」），疑似误报或 token 时间偏差，需要听音确认。

## 用 gold 评估说话人 / 声纹注册（2026-10-17）

- `../segmentation-gold/score_speakers.py`：用 30 期 gold（5 分钟，朱李/理名）评估 diarization.json。
  - pyannote 整期自动：帧准确率 70.1%，逐行 63.5%，换人点召回 21/94；`--num-speakers 2`（整期/只跑切片）几乎没变化（68–70% / 62–65%）。结论：不是簇数问题。
- `embed_probe.py`：只取 gold 中单人且有字的片段提取 community-1 声纹，留一法最近中心准确率：≥1s 86.9%（≥2.5s 94%），≥0.5s 89.4%（0.5–1.5s 88.5%）；无监督 KMeans(2) 88%。结论：**声纹本身能分开两人，问题在 pyannote 的聚类**，适合改为“注册声纹 + 按相似度判定”。
- `koelog_clips.py` → `runs/koelog/clips.json`：自动定位各期声ログ录音（台标「…トゲラジ」到标题「声ログ」之间；31 期作为测试素材排除）。43/44/47/49 期未定位到。

## 寻找更强的说话人识别方法（2026-10-17）

模型权重都在 `.model-cache/speaker/`（已 gitignore，离线）：WeSpeaker ONNX `resnet221/ resnet293/ cnceleb34/model.onnx`、funasr `campplus/campplus_cn_common.bin`、speechbrain `ecapa/`（加载失败：hyperpyyaml/ruamel 版本不兼容，未修）、`wavlm-sv/`（microsoft/wavlm-base-plus-sv）、`redimnet/M-vb2+vox2+cnc-ft_mix.pt`。下载渠道：hf-mirror.com（模型）、github release；CAM++ 与 ReDimNet 的模型代码放在 `third_party/`（ruff 已排除）。

- `bench_spk_models.py`：同一批注册段（907 段）+ 30 期 132 个 gold 单人片段，逐模型提声纹（缓存 `runs/bench/<model>.npz`），比较 centroid / knn5 / logreg / lda 后端，`--fuse "a,b;c,d"` 拼接融合。

  | 模型 | centroid | knn5 | logreg | lda |
  |---|---|---|---|---|
  | pyannote community-1 (ResNet34) | 88.6 | 91.7 | 88.6 | 90.2 |
  | WeSpeaker ResNet221 / ResNet293 | 89.4 / 90.2 | 88.6 / 89.4 | 89.4 / 90.2 | 90.2 / 87.9 |
  | WeSpeaker CN-Celeb ResNet34 | 91.7 | **92.4** | **92.4** | 89.4 |
  | CAM++ (中文 common) | 90.2 | 90.9 | 89.4 | 88.6 |
  | ReDimNet-M | **92.4** | 90.2 | 91.7 | **92.4** |
  | WavLM-base-plus-sv | 81.1 | 78.0 | 78.8 | 78.0 |
  | 融合（2–6 个模型拼接） | 91.7–92.4 | 90.9–91.7 | 91.7–92.4 | 不稳定 |

  结论：换模型 / 融合都卡在约 92%。**剩下的错误几乎全是同一段**：497–518s 的来信朗读（gold 标理名，上一句「ラジオネームポッサムさん」是朱李），6 个模型全部、包括 3.7s 的长片段都判为朱李；后面的逐帧分类器也一样。很可能是 gold 标注错误（待用户听音确认，切片时间 0:02:02–0:02:23）。把这 10 行改成朱李后（`$PI_SCRATCH_DIR` 里的临时副本，gold 原文件未改）片段级约 97–99%。
- `segenroll_diarize.py`：保留 pyannote 的分割/计数/局部声纹/重建，只把全局聚类换成“每个 10s 块内局部说话人与在场成员做匈牙利匹配（注册中心或 logreg）”。帧 70.6% / 逐行 65.9–66.5% / 换人召回 23–24/94，与 pyannote 原版几乎一样 → **pyannote 的短板在分割模型**（块内把两位主持人合成一个局部说话人），不是聚类，这条路不用再走。
- `frame_spk.py`：闭集逐帧说话人分类。冻结 WavLM base-plus（取自 `wavlm-sv`）第 2/4/6/8 层 → 2 层 BiLSTM → 理名/夕莉/朱李 三类，50 帧/秒；用 #15/16/18/20/21 ASS（只用恰好一人覆盖的帧）+ 声log 区间训练（理名 887s / 夕莉 1219s / 朱李 506s，3000 步约 2 分钟），30 期不参与训练。推理限定在场成员、有无语音沿用 pyannote，`--adapt-rounds` 可在本期高置信帧上做伪标签自适应（不用 gold）。

  30 期 5 分钟（左：原 gold；右：497–518s 改为朱李）：

  | 方法 | 帧准确率 | 逐行 | 换人点召回 |
  |---|---|---|---|
  | pyannote 自动 | 70.1 / 77.4 | 63.5 / 69.5 | 21 |
  | segenroll（pyannote 分割 + 注册分配） | 70.6 / 77.0 | 65.9 / 70.7 | 24 |
  | 注册滑窗 窗0.75 步0.1 平滑0.3 | **79.2 / 86.6** | 78.4 / **84.4** | 50 |
  | frame_spk | 78.1 / 84.4 | 77.2 / 82.0 | 50–51 |
  | frame_spk + 自适应 1 轮 (conf≥0.97) | 78.5 / 84.9 | **79.0** / 83.8 | **54–55** |

  诊断（改后 gold，注册滑窗 vs frame_spk+自适应）：两法 92% 的帧一致，一致处准确率 94%；**70–77% 的剩余错误落在 gold 句子边界 ±0.3s 内**（该区域只占 45% 帧）。换人漏检按类型：普通换人 22–24/37、新轮次<0.8s 13–18/24、重叠插话 11–13/31、涉及 others 0/2；大部分漏检是前一句短句身份判错，少数疑似 gold 问题（如 616.5s 4 秒长句 gold 理名、两法都判朱李）。
  结论：**“是谁”已基本解决，剩余误差是边界精度 + 插话/重叠**，再换更强的声纹模型收益很小。下一步应把说话人后验按 ASR 词级时间戳投票（每词/每句取多数），重叠插话需要支持多标签（frame_spk 可改为 sigmoid 多标签并用 ASS 重叠帧训练）。所有参数只在 30 期一个 5 分钟切片上比较，需要第二期 gold 复核。

  结论：**注册滑窗 + ReDimNet-M 是目前最稳的方案**（4 期中 3 期帧准确率最高，换人召回 4 期中 3 期最高，比 pyannote 自动高 8–19 点）；frame_spk 在 30 期上看着接近，但留一期复核明显更差（训练数据太少、对没见过的期泛化差），**不推荐**；逐期中心自适应会把初始错误自我强化，**不推荐**。离开 gold 边界 0.3s 以外的帧，#16/#18 准确率约 94–95%；剩余误差主要是三人同场时理名↔夕莉混淆（#16 理名召回约 67%）和句子边界/重叠插话。

## 说话人强制切分（2026-10-17）

- `enroll_diarize.py --save-scores` 额外输出 `frame_scores.npz`（10ms 帧 × 在场成员，未平滑的平均余弦）。
- `speaker_split.py`：把每条字幕的 ASR token 按帧分数投票定人，相邻同人 token 成段；置信不足的段（平均差值 < `--min-margin`，或时长 < `--min-dur` 且差值 < `--strong-margin`）并入相邻段，只在剩余段界切开。文字不改，内侧边界取 token 实际时间。
- 30 期 token 级判定：内容 token 准确率 95.1%（gold 有重叠的行 93.2%，无重叠 96.6%）；差值 ≥0.2 的 474 个全对，<0.05 的只有约 64%。
- 接在 Gemini 合并（split_segments）后，30 期 gold（基线 正确条 71 / 错切 15 / 漏切 33/79 / 改坏 0）：
  - `--min-margin 0.05 --min-dur 0`：93 / 23 / **11** / 改坏 5
  - `--min-margin 0.1 --min-dur 0`：**86 / 16 / 23 / 改坏 0**（目前最均衡）
  - `--min-margin 0.15`：76 / 15 / 30 / 0
- 担心的重叠问题确实存在：低阈值新增的错切几乎都落在 gold 两人重叠处（如 410.85s、415.57s、425.25s、595.95s、604.03s，一人说话时另一人插话/齐声），说明“强制切开”不能只看声纹。
- 试了两种重叠处理，**都无效，不采用**（2026-10-18）：
  - 叠加行（`--overlay-max`：A|B|A 且 B 短于 N 秒时，B 单独作叠加行、A 拼回一条）：0.1 阈值 正确条 86→85，0.05 阈值 93→87。被选中的 B 多数是真正的轮流说话（「悠長不動悪くはないんです」「えパンを食べたことは」），gold 里 A 的两段本就是独立单元。以后只对附和词考虑叠加，而附和词本来也可以删。评分器 `score_gold.py` 已支持 manifest 里的 `"overlay": true`（第二轮对齐剩余 token）。
  - 重叠区（pyannote 分割计数 ≥2，30 期共 127 段 88.8s）提高阈值：0.05 阈值多出的 8 个错切里 4 个在重叠区内或 0.1s 内，12 个正确新增里也有 6 个，分不开。
  - 结论：保持 `--min-margin 0.1 --min-dur 0`。
- 同时修了 normalize：按词尾/词头规则的悬空短语拼接默认关闭（`--join-fragments` 可恢复），结尾延长/吸附保留。30 期：正确条 67→77、漏切 33→28、改坏 12→2。节目记忆改为也匹配相邻两条拼起来的文字（53 期「赤色の｜共済を」这类仍能修）。
