# 迁移与发布范围

## 历史保留方式

发布分支从原远端 main 的 `1d7a3bd0e8add7f5f2180d01522d1d82db901f3d` 建立，正常追加提交，不删库、不强制推送、不合入内部审计仓库的历史。

业务来源分别为模块化候选 `ed8c2c248b9a8d227b095f1b42040121c9b279d5` 和旧业务基线 `764a39787ff94fb80180420a68e1bbac0d9c73c8`。后者不是原远端 main 的同一版本；不能把整个发布差异描述为纯移动文件。来源及有界发布适配见 `runtime/source-provenance.json`。这些提交号仅作来源说明，构建/测试不要求下载相应 Git 历史。

## 布局变化

- 旧 `qwen_asr/`、`optimizer/` 移到 `compat/legacy/`。根目录 `main.py`、`webapp.py` 显式加载这一目录。
- 旧提示词、CI presets、必要节目资源、测试/工具和部署示例随兼容源码保留。大媒体、声纹嵌入、模型及个人术语工作簿不随发布。
- 固定链与相关阶段适配器位于 `modules/temporary/`。本次仅选择当前固定链依赖闭包，不宣称本地审计仓库的全部迁移模块已公开或生产放行。
- `runtime/registry-templates/` 是可移植输入。`module-registry/` 含本机依赖摘要，必须本机构建，不跟踪提交。
- 宿主相对 `legacy_sources.root` 以传入的 project 根解析，不再硬编码开发者旧仓库位置。已声明兼容源码在转换时逐文件确认仅有 LF 换行归一化，未因此改变业务算法。
- 差分测试使用 `tests/fixtures/baselines/` 中的冻结源码及 SHA 索引，替代内部 `git show`。夹具仅做同样的仓库路径适配，不改旧行为。

## 不应推送的内容

`.gitignore` 排除运行输出、模型、缓存、虚拟环境、生成 registry、验证日志和私有 env 文件。不要强制添加这些目录。

本发布没有复制编号过程文档、工单、会话交接、全仓模块台账及批量运行证据。它们留在原本地审计仓库。Markdown 提示词、实际工具说明和第三方许可证属于功能或许可证依赖，不按后缀一律删除。

术语资源保留原始来源字段，其中可能出现旧开发路径或内部文档名；这些仅作历史出处，不用于文件装载，也不要求获取该路径。

安装说明中的两份 docs 与根 README 是本发布的主要使用文档；旧兼容工具 README 和运行时提示文档另行保留。第三方 RedimNet 的 LICENSE 原样保留；本次不另行变更项目许可。

## 语义与验证边界

发布适配修复的是源代码位置、环境绑定和自包含测试，不改变质量阈值、内容保护、在线 opt-in 或真实执行开关。历史业务质量失败不会改写成成功。

旧的 episode-specific 实验模式仍有历史素材依赖；历史档案未随发布时应如实失败，不用复制私有档案或放宽检查来让它们“通过”。面向当前固定链的入口是 `real_chain_runner/launch.py`，不是历史重放计划。

本分支应先审阅再合并 main。推送发布分支本身不表示真实模型、服务部署、完整字幕质量或所有旧工具已经验收。
